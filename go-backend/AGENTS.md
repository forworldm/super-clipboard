# AGENT.md — go-backend 协作与变更指南（Best Practices）

> 目标：让任何代码代理（或新开发者）在 **不破坏 API 兼容性与数据一致性** 的前提下，稳定演进该 Go 后端。

---

## 1. 项目定位与核心约束

- 本目录是 Python `backend/` 的 Go 等价实现，优先保证：
  1. 前端 API 兼容
  2. SQLite 数据兼容
  3. 磁盘文件布局兼容
- 修改时默认遵循：**最小改动、可审查、可回滚**。
- 除非需求明确，避免“大重构/全量改写”。

---

## 2. 架构边界（必须遵守）

- `internal/api/*`：HTTP 层（路由、鉴权、状态码、响应体）
- `internal/schemas/*`：请求/响应结构与校验（422 错误形状）
- `internal/repository/*`：SQLite 访问与事务一致性
- `internal/storage/*`：纯文件 I/O（chunk、组装、落盘）
- `internal/config/*`：环境变量与配置归一化
- `internal/apperr/*`：跨层错误类型与错误码

**禁止跨层泄漏**：
- storage 不应依赖 api/repository
- repository 不应依赖 api
- api 层不要直接拼 SQL

---

## 3. 错误处理规范（Go 范式）

- 严禁用中文/英文错误字符串做业务分支判断。
- 优先使用：
  - `errors.Is`（哨兵错误）
  - `errors.As`（类型错误）
  - `apperr.ValueError.Code`（稳定错误码）
- 用户可见 message 可保留中文；**分支逻辑必须依赖类型/Code**。
- API 层统一走 `writeError(...)`，保持错误体一致。

---

## 4. 安全与鉴权（重点）

### 4.1 管理员 API

- 管理员接口必须严格鉴权。
- 当前策略：`Authorization: Bearer <token>` + 常量时间比较。
- 未配置 `SUPER_CLIPBOARD_ADMIN_API_KEY` 时，管理员路由返回 `404 Not Found`（不暴露能力）。
- 鉴权失败返回 `401`，并带 `WWW-Authenticate`。

### 4.2 通用安全要求

- 禁止把 secret 写入日志（token、captcha secret、admin key）。
- 文件路径相关逻辑必须做 path traversal 防护。
- 输入参数必须先校验再进入存储层。

---

## 5. 并发与一致性

- Repository 的锁只保护短事务，不要把慢 I/O 放锁内。
- chunk 上传/合并流程：
  - 文件 I/O 与 DB 状态转换要有明确边界
  - 出错必须可恢复（可重试/可回滚）
- 涉及状态机（active/completing/completed）时，优先 CAS 语义 SQL（带状态条件更新）。

---

## 6. API 兼容性策略

- 修改接口前先确认：
  - URL、方法、状态码
  - 响应 JSON 字段名与类型
  - 失败时 `detail` 格式
- 对外新增字段应尽量向后兼容（增量字段 > 修改字段）。
- 若需破坏性变更，必须在文档中显式标注迁移策略。

---

## 7. 数据库与迁移

- 仅做增量兼容迁移（`IF NOT EXISTS`、可安全 `ALTER`）。
- 避免需要人工介入的迁移步骤。
- 新增索引时评估写放大与查询收益。

---

## 8. 测试实践（每次改动都要做）

- 先补/改测试，再改实现（至少并行推进）。
- 覆盖三类场景：
  1. 正常路径
  2. 权限/参数错误路径
  3. 并发或边界路径（能覆盖就覆盖）
- 管理员 API 至少覆盖：未启用、未授权、授权成功、关键操作成功/失败。

---

## 9. 提交前检查清单（必做）

1. `gofmt -w` 变更文件
2. `go test ./...` 全通过
3. 关键接口手工验证（若改了行为）
4. 无敏感信息泄漏到日志/响应
5. README / docs 需要时同步更新

---

## 10. 推荐变更风格

- 小步提交：每个提交只解决一类问题。
- 注释写“为什么”，少写“做了什么”。
- 复用已有 helper，避免复制粘贴逻辑。
- 新能力优先放在独立文件（如 `admin.go`），降低耦合。

---

## 11. 常见反模式（避免）

- `strings.Contains(err.Error(), "...")` 决策业务分支
- 在 handler 中堆积大量 SQL/状态机逻辑
- 引入全局可变状态绕过 repository
- 未鉴权开放调试/管理端点
- 只测 happy path，不测拒绝路径

---

## 12. 维护者提示

当你不确定某行为是否应兼容 Python 版时，优先：
1. 看现有 Go 测试是否已定义行为
2. 看 API 使用方（前端）是否依赖该行为
3. 做“兼容优先”的最小改动并补测试锁定行为
